# Migration scope

The 2026-10-19 migration reviewed the main 41-skill source estate and the current personal skills installed on the Mac. Additional sources were the older plugin archive, the account-upload archives, and a third-party resume collection. Duplicate worktrees and dated copies were treated as historical evidence. The source directories remain intact.

| Source group | Disposition |
| --- | --- |
| Main business and delivery estate | Re-authored portable workflow instructions. Branding and operating requirements route to shared policies. |
| Older plugin archive | Recovered ten useful workflow scopes: business case, deal desk, playbooks, kickoff, UAT, jobs to be done, and solo delivery operations. |
| Current personal skills, including career and evidence workflows | Retained current methods and supporting resources. Removed the former employer's identity. Corrected references to unavailable private bundles. |
| Third-party resume archive | Kept as historical source. Current career workflows govern the new estate; unsupported ATS and outcome claims were not carried forward. |
| Sticker and game skills | Added adapters to current project authorities. Each project retains its own assets and tools; game records remain with the game project. |
| Brand and estate operations | Added a canonical brand profile and skills for sync and GitHub access. Build tooling records package hashes. Installation produces restore receipts. CI validates repository changes. |

The repository has 48 rebuilt workflow skills, 21 retained current personal and career skills, two project adapters, and three foundation skills. The generated catalog is the exact package inventory.

## Excluded dependencies

The migration does not copy the former employer's logos, licensed fonts, fixed commercial rates, margin thresholds, remittance details, legal clauses, real customer fixtures, or private service endpoints. It also excludes the bespoke rendering and integration engines whose behavior depended on those materials. Their historical copies remain available for separately scoped adapter work.

Portable workflows use tools actually available in the running host. A Salesforce, document, deployment, or research workflow can require a connected tool and authorized source data. The presence of its skill does not establish that connection or prove a real deployment.

Private career claims, resumes, Brain records, and project ledgers are external authorities. The corresponding skills explain how to locate or request that evidence. They do not ship those records to another account. Local path adapters require the mounted source volume or an explicitly supplied equivalent.

## Verification boundaries

Packaging tests cover policy propagation and stale builds, including source changes during a build. Installation tests exercise conflict detection and failed-operation rollback. They also verify backup creation and restoration. Account-state tests distinguish a reported upload from runtime verification. Validation checks entrypoint names, descriptions, linked resources, and common credential patterns. These checks do not prove each business workflow's content quality, output rendering, host discovery, or service integration.

Local installation, a GitHub commit, an account upload, and a successful host invocation are recorded as separate states. Account copies are never overwritten by editing a platform-managed `synced/` folder. A changed canonical package needs a new account upload where the host has no supported repository sync.
