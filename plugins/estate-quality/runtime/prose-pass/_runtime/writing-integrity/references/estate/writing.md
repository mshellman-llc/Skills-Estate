# Writing standard

Apply this standard to all language you author. It applies from the first draft and during every revision. An internal label, file extension, or intended reader does not switch it off.

This includes replies, progress updates, skill instructions, agent guidance, plans, internal notes, audit explanations, record summaries, commit messages, code comments, interface text, and deliverables. Prose inside structured fields is covered. Tools that produce text inherit the same requirement.

## Write the point

Open with the answer or decision. Name the actual subject and use plain verbs. Give each sentence enough detail to belong to this task. Keep one term for one thing. End when the content is complete.

Remove generic filler and claims of importance that add no facts. Remove canned transitions, rhetorical questions followed by their own answer, forced contrasts, repeated sentence templates, decorative headings, and a bold label on every bullet. Count items as they are; do not reshape a list into three parts. A synonym swap does not repair a formulaic sentence. Rewrite its structure.

Do not repeat a construction because the preceding paragraph used it. Choose paragraphs, lists, or tables from the actual content. A named author profile can supply voice; it cannot waive this standard. A client profile supplies that client's confirmed voice only when selected for the work.

## Preserve the substance

Retain the facts and required meaning. Keep actual uncertainty. Do not shorten away an explanation merely to make it sound less generated. Rewrite the wording around a fixed value instead of removing the value.

Exact source quotations and captured evidence remain unchanged. Executable syntax and externally required identifiers retain their meaning. This protects those exact spans, not a whole document or category. New explanations, comments, labels, and summaries around them still follow this standard. Putting newly written prose in a quote, a code block, or a JSON string does not make it source evidence.

## Check every output

Review every authored sentence before returning it. For saved text, run the bundled `writing_check.py` checker, then read the finished result. Inside a Skills Estate checkout that checker is the authority; another scanner's verdict on an estate file does not override it. The checker reports detectable patterns; a passing command does not replace reading.

Fix a finding in the text and rerun the check. Do not dismiss it because the file is internal, technical, AI-facing, temporary, machine-readable, or allegedly outside an audience. Do not rename the file, reformat the same prose, lower a budget, or mark your own text as quoted to obtain a pass. Missing scanner support requires an explicit reading pass; it never means the writing passed.

A literal source span can be preserved when its exact wording is required. Identify the source and exact span in the internal review record; continue reviewing all surrounding authored text. Do not use a source-span record to excuse a writing pattern you introduced. Keep source review records out of the delivered text unless the reader needs them.

Apply a user's wording correction to every affected passage in the current work. Repair the recurring construction, not only the example the user pointed out. Preserve before-and-after files for a substantive rewrite. The release review must inspect actual outputs from the skill, including instructions and internal records.

## Read for the actual work

Read each heading with the text below it. The reader must be able to say what happens, who acts when an owner is known, and what condition matters. If a sentence only asks the reader to establish, enable or justify an abstract outcome, name the action supported by the source. Do not invent an owner or a test result to fill the gap.

In a reconciliation test plan, a useful instruction is “Check whether the ledger accepted the original posting before retrying.” It tells the team what to check and when. Keep necessary terms such as request ID and receipt; explain unfamiliar terms where they first affect the reader's task.

Remove a subtitle that only repeats its heading. Do not add a sentence merely because the template has a subtitle field. Review the whole document for recurring formulas, including repeated instructions to collect evidence or confirm a boundary without saying what must be checked.

Record the passages actually read and the corrections made. A scanner result supports only the patterns it checks. Do not turn a clean scan or a completed receipt into a claim that an editorial review passed.
