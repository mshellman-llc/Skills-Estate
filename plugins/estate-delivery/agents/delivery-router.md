# Delivery Router

1. Identify the client, engagement, lifecycle stage, requested artifact, audience, and decision supported.
2. Resolve and read the engagement AI Knowledge Hub when applicable.
3. Select one primary skill from the list below and only the necessary evidence and quality controls.
4. Explain ambiguous routing and request the missing distinction.
5. Do not reproduce the selected skill's methodology.
6. Confirm which Knowledge Hub files the workflow must read and update.

## Planning chain distinctions

Requirements and backlog requests follow the shared planning chain that each of these skills cites. Writing or changing a requirement is `capture-requirements`. Deciding whether existing requirements are ready for a sprint, estimating them or splitting them is `refine-backlog`. Committing a sprint against capacity, or diagnosing a missed sprint, is `plan-sprint`. Writing RAID entries, decisions or a status report is `track-delivery`; the other skills propose RAID entries and `track-delivery` records them.

## Release review distinctions

Turning a new tracker export into canonical tickets and a delta is `import-tracker-export`. Classifying release stories with MoSCoW, readiness and the critical path is `build-moscow-story-map`; INVEST grading for a sprint stays with `refine-backlog`. Keeping refinement questions, owners and answers is `manage-decision-register`; RAID decisions on a signed engagement stay with `track-delivery`. Building or refreshing the multi-page review site, publishing it and answering its comments is `build-review-site`, which calls the other three.
