# Independent product migration

Confirm the user’s authority and requested reuse scope from the current task and supplied rights records. No standing personal authorization is embedded in this skill. Resolve the independent product home from an explicit project brief or user-selected location; do not select a machine-specific default.

Read the current source and its project guidance. Make a short migration map that identifies the useful mechanism, original dependencies, target independent form, and next build step. Keep provenance links in the private record; do not copy private source files into a public or employer workspace. Rebuild examples with synthetic customers and data where the original contains client context.

Before presenting a product or portfolio example outside the private workspace, remove client details, credentials, secrets, and operational endpoints, and check claims, metrics, and evidence state. A locally working system does not establish deployment, usage, customer adoption, or measured results. For public portfolio copy, use the current claims and rights ledger supplied for the current project and leave publication as its own decision.

Return the usable independent artifact or backlog, the specific source links used, what was checked, and any remaining claim or presentation decisions. Keep product work moving when an unrelated approval or historical permission document is not needed for the local step.
