# Journey mapping

Map one actor's experience and choose an improvement to validate. Produce the journey, its service blueprint and a prioritized opportunity map from supplied evidence.

Before drafting, read the complete [journey method](references/method.md). It contains the required inputs, labeled-hypothesis mode, eight journey lanes, blueprint boundaries, phase presets, opportunity criteria and release checks. Read it in bounded parts if the tool would clip its output; a partial read cannot establish coverage. Load its linked template for the requested views, and the rendered layout only when producing HTML. Resolve the skill directory first and run the method's relative commands from that directory.

Confirm the actor, starting and ending events, current or proposed state, and the decision. Keep phase references consistent across all three views. Retain reported feelings at their steps without inventing scores. The actor's own actions belong in front-stage. Unknown visibility and unsupported causes stay unknown.

For HTML, use [the starter and data instructions](references/rendered-map-layout.md). Keep JSON as the editable map source and rebuild the HTML after changes. A Markdown-only request receives all three views inline. When HTML carries the journey and blueprint, the narrative explains the recommendation and supplies its sources and validation questions without copying the full board again.

Review the actual output against its sources. Explain how the proposed intervention changes a step and which measure can test it. Check captured feelings, both blueprint boundaries, source attribution and the timing of the recommendation. Run the method's applicable release checks; report a missing check instead of claiming a pass.
