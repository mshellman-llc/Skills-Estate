# System Design

> Produce a fast, unbranded working design for a new system, service, API, or data architecture, usually inline.

**What it does.** Covers requirements, components, data flow, data model, API contracts, storage, caching, queues, scaling, reliability, capacity, and explicit trade-offs.

**Use it when.** Someone asks how to build or structure a new product or service, how it will scale, which database, cache, queue, or API style fits, or wants component boundaries explored before decisions are formalized.

**Formal references.** Use the embedded formal architecture reference mode for a sourced architecture or engineering document. It retains source authority, diagrams, security boundaries and artifact review.

**Scope.** Standalone code review and a short record of an already-made decision are separate tasks. Inspect the existing system when designing an extension.
