# Deck builder

Read [shared workflow](references/estate/workflow.md). For a rendered or branded artifact, read [brand policy](references/estate/brand.md) before choosing visual values. These references are generated from the canonical policies when the estate builds.

Identify the audience, decision, current belief, desired action, and available evidence. Form a single supported thesis that explains the decision. A service name or list of features is not a thesis. Resolve a material choice of argument with the user; otherwise continue within the supplied brief.

Break the argument into the submessages it needs, then order slides so each advances it. Write slide titles as claims supported by the slide body. Choose charts, diagrams, tables, and examples for the information they show. Avoid a fixed number of cards or bullets.

Draft copy before polishing visual details. Preserve source-backed metrics and required qualifiers. Apply the selected brand profile, then use the available presentation tool to build the editable deck. Retain the requested aspect ratio, slide count, and template when supplied.

Render every slide. Check overflow, legibility, alignment, chart labels, contrast, source notes, and speaker notes. Compare rendered text and numbers with the approved content. Fix repeated layout defects throughout the deck. Save reusable project lessons only when the user authorizes that update. Deliver the deck and state any unresolved content or rendering issue.
