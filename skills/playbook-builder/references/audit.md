# Auditing a catalog against findings

An audit compares an existing catalog against a fresh input (a conference brief, market research, a strategy memo, a competitor scan) and answers: where is the catalog already aligned, where are the gaps, and what should change.

## Method

1. **Extract the input's themes.** Reduce the findings document to a short list of distinct themes or principles (usually 5 to 9). Each becomes an audit row.
2. **Score each theme against the whole catalog, not play by play.** For each theme, name which plays already embody it and where the gap is. This reads far better than a giant play-by-theme matrix and surfaces the real gaps faster.
3. **Rate the status honestly.** Strong / partial / missing. Resist grading everything "strong"; the value of an audit is the honest gap.
4. **Name one action per theme.** None needed, an enablement asset, a wording fix, a new play, or a flag for a human.
5. **Call out the single biggest gap** explicitly, above the table, so it does not get lost among the aligned rows.
6. **Detect duplication.** If the input or the catalog reveals two plays occupying the same slot, apply the add-vs-replace decision from the main skill.
7. **Collect decisions.** Anything that needs a human (a fee band, a routing rule, a numbering scheme, a boundary call) goes in a single "decisions requiring human input" list at the end. Do not resolve these silently.

## Discipline

- Ground every claim in either the catalog or the input. Do not import outside "best practice" the sources do not support.
- If the input recommends something the catalog deliberately does not do (for example, an outcome-based pricing component the catalog omits on purpose), note it as a conscious omission rather than an automatic gap.
- Never fabricate a figure to make a gap look quantified.

## Deliverable structure

Use `audit-template.md`. In short:

- **Headline**: the one-sentence finding and the recommended move.
- **Part 1, catalog vs findings**: the theme table (Finding | Catalog status | Action), with the biggest gap called out above or below it.
- **Part 2, duplication finding** (if any): the two plays side by side, and the replace-or-add recommendation with reasons.
- **Part 3, drop-in replacement or new entry** (if any): the affected entry rendered in full house format, ready to paste into the corpus.
- **Part 4, new play** (if a gap warrants one): rendered in full house format, with any un-groundable parameters left open.
- **Part 5, decisions requiring human input**: one consolidated list.

Keep the parts the audit actually needs; drop the ones it does not.
