# Session handoff

Read [shared workflow](references/estate/workflow.md). For a rendered or branded artifact, read [brand policy](references/estate/brand.md) before choosing visual values. These references are generated from the canonical policies when the estate builds.

Use the conversation and work performed in this session. Record the timestamp, working directory, repository branch and commit when available, and whether the working tree has changes. A handoff is a dated snapshot.

Preserve the user's original outcome, later corrections, accepted decisions, scope limits, completed work, unresolved work, and abandoned approaches that matter to resumption. List exact file locations and the governing plan or source authority. Never substitute the latest small subtask for the original objective.

Record any running processes, session IDs, temporary worktrees, pending tool calls, uncommitted changes, and required user input. Include focused verification commands with expected results and the exact next action. Do not mark a linked task complete merely because the chat is ending.

Use the requested destination or the project's handoff location. Keep secrets and raw private evidence out of the handoff. Report where it was saved; when persistence is unavailable, provide the handoff in chat and say so. Do not update long-term memory unless the user explicitly requests it.
