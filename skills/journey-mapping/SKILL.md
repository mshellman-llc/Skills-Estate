# Journey mapping

Read [shared workflow](references/estate/workflow.md). For a rendered or branded artifact, read [brand policy](references/estate/brand.md) before choosing visual values. These references are generated from the canonical policies when the estate builds.

Identify the actor, scenario, journey boundary, outcome, and intended decision. Read interviews, operational records, existing maps, and system evidence. Separate the current state from a proposed future state.

For each phase, record the actor's goal, actions, touchpoints, needs, emotions when actually supported, friction, and source. Do not infer emotion from a process diagram or label one interview as universal behavior.

For the service blueprint, connect visible interactions to backstage work, systems, data, owners, handoffs, and failure points. Show where responsibility or evidence is missing. Use the same phases and IDs across journey and blueprint.

Build an opportunity map that links friction to an intervention, expected outcome, owner, dependencies, effort basis, and a way to measure it. Distinguish reported severity from your prioritization. Reconcile the three views before rendering. Preserve source limits and make the proposed next decision clear; a future-state map does not prove the process has changed.
