1 · Orientation

The sample review must retain source identity

This newly constructed exercise uses fictional documents and test endpoints. A submitter supplies a source revision. A reviewer records a decision, and an export adapter writes the accepted result. The exercise contains no real client, employee, quote or operational incident.

The source record remains read-only. An invalid identifier stays pending. An export with an uncertain outcome must be reconciled before retrying. Those requirements are fixture inputs, not statements about any deployed product.

5 · Information model

Keep source and review records separate

A synthetic input folder contains files with inconsistent labels. The fixture provides no reliable relationship between a file and a review decision.

  • sample-one.txt
  • sample-two.txt
  • sample-three.txt

The proposed exercise uses three record types with explicit identifiers.

  • Source: document identifier, revision and immutable content reference.
  • Review: source revision, authorized reviewer, decision and reason.
  • Export attempt: review identifier, operation key, destination and confirmed result.
6 · Failure handling

Resolve uncertain exports before retrying

A completed result and an unfinished attempt are different states. The adapter claims an operation key before writing. If a timeout leaves the outcome unknown, it queries the destination using that key. A confirmed result completes the local attempt; an unresolved result remains pending.

This is a design hypothesis to test with the supplied adapter. It does not establish exactly-once behavior or authorize an external write.

8 · Review questions

Check the boundaries before implementation

Can the source file be edited during review?

No. This exercise preserves the supplied revision and creates a separate review record. A changed source requires a new review.

Does a matching owner name grant access?

No. The caller must have the required permission for the selected record and action.

What happens after an ambiguous timeout?

The adapter reconciles the prior attempt before sending another write.

9 · Open decisions

Confirm the adapter and retention rules

The fixture intentionally leaves the destination protocol and record retention period unspecified. Obtain these from the current project before implementation. The calculator above does not resolve either decision.
