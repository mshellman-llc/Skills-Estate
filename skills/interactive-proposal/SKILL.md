# Interactive proposal

Read [shared workflow](references/estate/workflow.md). For a rendered or branded artifact, read [brand policy](references/estate/brand.md) before choosing visual values. These references are generated from the canonical policies when the estate builds.

Choose priced proposal mode or unpriced explorer mode. In proposal mode, use an approved quote and record its revision. In explorer mode, show scope and unresolved decisions without currency or invented fees.

Create one data record per option containing its name, included and excluded scope, team assumptions, timeline, dependencies, and next action. Proposal records also carry the quoted price, pricing model, and source field. Present fixed quoted options; do not expose a calculator that silently reprices work.

Build the requested local page or site with accessible controls and useful keyboard navigation. Keep content usable without hover and provide a print view. Apply the shared brand policy. Do not embed private source records, record IDs, credentials, or internal commentary in a page intended for a client.

Test each option and its default state, displayed totals, exclusions, sources, narrow-screen layout, and print output. Compare the rendered options with the data records. Explorer mode must remain free of price claims. Creating a local page does not publish it; verify the destination separately when publication is authorized.

## Source contract and release checks

Read [the option contract and release checklist](references/option-contract.md) before building. Preserve the client's actual option decisions; do not convert internal estimate confidence bands into prospect-facing options.

An unpriced explorer omits unsupported staffing and duration commitments as well as currency. Explain the absence near the top and use a reproducible source-based count only when it helps the decision. Keep excluded scope visible and explain the supported route for addressing it. Validate every option's final state, accessible controls, sources disclosure, and print output against the same data records.

## Compose and review the complete experience

Read [proposal experience and content review](references/experience-patterns.md) before drafting. Restore the full decision journey: option comparison, relevant system behavior, named delivery dependencies, supported next action and descriptive source disclosures. A selector and price list alone are incomplete. Run actual writing checks, review rendered content and pacing, and retain the observed evidence and unresolved limits.
