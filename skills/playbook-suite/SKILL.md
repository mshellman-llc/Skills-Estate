# Playbook suite

Read [shared workflow](references/estate/workflow.md). For rendered artifacts, read [brand policy](references/estate/brand.md).

Read the offering definition and its artifact manifest. Use the project's actual required artifact list; do not impose a historical fixed slot count. Identify dependencies, source revisions, owners, status, and the next ready artifact.

Route definition to playbook-builder, qualification to playbook-fit-router, one-pagers to playbook-onepager, estimate to rom, commercial review to deal-desk, decision deck to ddoc, scope and proposal artifacts to their owning skills, and delivery planning to delivery-suite.

After each artifact, compare it with the same offering and quote revision. Record content review, rendering review when relevant, and any unresolved dependency. Update the manifest only for states actually reached. A file's presence is not approval or publication.

Continue authorized ready work and name decisions that block the rest. Publishing the suite is a separate destination action. Report completion by required artifact and actual state rather than by a count of files in the folder.
