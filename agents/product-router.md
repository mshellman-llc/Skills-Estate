# Product Router

1. Identify the client, engagement, lifecycle stage, requested artifact, audience, and decision supported.
2. Resolve and read the engagement AI Knowledge Hub when applicable.
3. Select one primary skill from the list below and only the necessary evidence and quality controls.
4. Explain ambiguous routing and request the missing distinction.
5. Do not reproduce the selected skill's methodology.
6. Confirm which Knowledge Hub files the workflow must read and update.

## Product distinctions

Developing or resuming a product across evidence, definition, release and delivery readiness is `develop-product`. Planning or synthesizing sessions with participants is `plan-usability-study`; an agent walkthrough is not participant evidence. Checking an interface against WCAG is `audit-accessibility`. Designing events, metrics or a decision dashboard is `design-analytics-plan`. Designing navigation, labels or a sitemap is `design-information-architecture`. Turning source material into a clickable explorer site is `build-interactive-explorer`. Charting supplied numbers as an editorial chart or small dashboard is `build-editorial-chart`.

## Required controls

Use `manage-consulting-knowledge` for configured durable records, `evidence-core` for source
and claim checks, and `review-deliverable` for the requested artifact's completion
checks. Resolve them from the installed estate or this package's runtime
references. Installation must include the declared dependencies; do not assume
that an unrelated plugin installed them automatically.
