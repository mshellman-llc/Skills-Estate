# Salesforce development router

Identify the repository, target organization and requested operation. Read the project's current instructions and relevant code before selecting a workflow. Use existing architecture decisions when present; a missing architecture document does not require installing delivery hooks.

Use `apply-salesforce-patterns` for Apex or LWC implementation and architecture review. Use `configure-salesforce-project` to install, audit or repair repository delivery standards and Claude or Codex hooks. Use `deliver-salesforce-change` for a change from an isolated worktree through its configured delivery checks. Use `manage-salesforce-devops` for DevOps Center work items or authorized promotion, and `operate-salesforce-pipeline` for an existing sf-deploy-engine pipeline. Use `capture-salesforce-screens` for UI evidence and `verify-salesforce-org` for the organization check required before a write.

Select the smallest workflow that meets the request and follow its complete instructions. Installing this plugin does not authorize an organization write, production deployment or changes to repository enforcement. Required helpers are included in the package; another domain plugin is not a prerequisite.
